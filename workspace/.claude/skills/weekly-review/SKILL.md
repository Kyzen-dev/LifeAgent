# بازبینی هفتگی (هفته شمسی: شنبه تا جمعه)

هدف: یک تصویر صادقانه از هفته + سه اولویت روشن برای هفته بعد. جمعه عصر است: لحن آرام، نه بازجویی.

## ۱. جمع‌آوری — یک دور موازی
شنبه این هفته و امروز را از خط `[اکنون: ...]` حساب کن (یا `date_convert`).
- کارها: `task_list` status=done limit=200 (فقط ردیف‌های `done_at` ≥ شنبه) + `task_list` overdue_only=true
- `habit_status` (done_this_week در برابر target_per_week، streak)
- `journal_recent` days=7 (روند mood/energy، موضوعات تکراری)
- مالی: `finance_list_transactions` start=شنبه end=امروز limit=200 + `finance_summary` (بودجه‌های ماه)
- فریلنس: `time_report` (پیش‌فرضش همین هفته است) + `project_list` (باز) + `pipeline_stats` days=7
  (و اگر پروفایل از Upwork می‌گوید، یک `pipeline_stats` days=7 source=upwork)
- `goal_list`
- سلامت: `health_history` metric=`weight` days=30 + شاخص‌های مرتبط با هدف پروفایل که ثبت می‌شوند
  (مثلاً `meals`، `workout_min`، `sleep_hours`، days=7). خطای «داده‌ای نیست» = آن شاخص را نیاور.
- فایل‌ها: آخرین `notes/reviews/*-weekly.md` (Glob → Read؛ اولویت‌های هفته قبل)، `notes/brand/log.md` (اگر هست)،
  و Grep «تاریخ‌های مهم|پیگیری» در `notes/people/` (skill `people-crm`) برای تولد/پیگیری ۷ روز آینده.
  و `notes/work/invoices.md` (اگر هست؛ skill `invoicing`): فاکتورهای sent/overdue و سررسید هفته آینده.
- اختیاری: اگر `mcp__google__*` هست، رویدادهای مهم هفته بعد؛ اگر `mcp__github__*` هست، PR/issueهای باز کاربر.

## ۲. تحلیل (اعداد واقعی، بدون ساختن)
- **اولویت‌های هفته قبل:** هر کدام ✅ / 🟡 / ❌ — این مهم‌ترین بخش پاسخ‌گویی است.
- **عادت‌ها:** درصد انجام نسبت به هدف هفتگی؛ بهترین و رهاشده‌ترین عادت (نام‌ها از habit_status).
- **مالی:** جمع هزینه هفته، ۳ دسته بزرگ، درآمدهای ثبت‌شده؛ بودجه‌هایی با `used_percent` جلوتر از درصد گذشته ماه.
- **فریلنس:** ساعت کل، درآمد تقریبی/نرخ مؤثر (فقط اگر نرخ ثبت شده)، پروپوزال/مصاحبه/استخدام هفته،
  پیگیری‌های عقب‌افتاده (`follow_up_due`) و مهلت‌های هفته بعد.
- **سلامت:** روند وزن ۲ هفته‌ای نسبت به هدف پروفایل (تغییر روزانه را تفسیر نکن)، و یک شاخص دیگر.
- **الگو:** یک مشاهده صادقانه و مشخص از داده‌ها (مثلاً «روزهایی که ورزش کردی انرژی ژورنالت ۲ نمره بالاتر بود»).
  اگر داده کافی نیست، الگو نساز.

## ۳. خروجی تلگرام (حداکثر ~۳۰ خط، بخش خالی = حذف، بدون جدول)
```
📊 **بازبینی هفته {تاریخ شنبه} تا {تاریخ جمعه}**

🏆 **دستاوردها:** • ... • ...
🔁 **اولویت‌های هفته قبل:** ✅ ... · 🟡 ... · ❌ ...
🌱 **عادت‌ها و سلامت:** {عادت}: ۵/۷ · ... · وزن: {روند}
💰 **مالی هفته:** {جمع} — بیشترین: {دسته‌ها} · ⚠️ {هشدار بودجه}
💼 **فریلنس:** {ساعت} · {درآمد/نرخ} · پروپوزال {n} / مصاحبه {n} · پیگیری عقب‌افتاده: {مشتری}
📣 **برند و انگلیسی:** {پست‌ها/تمرین‌ها} → {یک پیشنهاد}
🎯 **اهداف:** {هدف}: {پیشرفت} — {عقب/جلو}
👥 **افراد:** {تولد/پیگیری هفته بعد}
🔍 **الگو:** ...
📌 **هفته بعد:** 1) ... 2) ... 3) ... {+ رویدادهای مهم}
```
اولویت‌ها: مشخص، قابل‌سنجش، و هر کدام به یک هدف یا مهلت وصل (مثلاً «۳ پروپوزال Upwork تا سه‌شنبه»).
اگر هفته سنگین بوده، اولویت کمتر بده نه بیشتر.

## ۴. ذخیره و سؤال پایانی
- **قبل از ارسال**، خلاصه را در `notes/reviews/YYYY-MM-DD-weekly.md` (تاریخ میلادی امروز) ذخیره کن؛ خط اول
  یک جمله خلاصه، و بخش «اولویت‌های هفته بعد» دقیقاً همان سه مورد (هفته بعد با آن مقایسه می‌شود).
- یک سؤال: «این ۳ اولویت را به‌صورت کار ثبت کنم و پیشرفت اهداف را به‌روز کنم؟»
  `[[options: ✅ ثبت کن | ✏️ تغییر می‌دم | ❌ نه]]`

## ۵. نوبت بعد
- «ثبت کن» → برای هر اولویت `task_add` (priority=2، due در هفته بعد، area مناسب)؛ برای اهدافی که شواهد پیشرفت
  دارند `goal_set` (id + progress). خلاصه یک‌خطی بده.
- «تغییر می‌دم» → اولویت‌های جدید کاربر را جایگزین کن، فایل review را Edit کن، بعد ثبت کن.
- برای تولد/پیگیری افراد، اگر یادآوری نیست، پیشنهاد `reminder_add` بده (skill `people-crm`).
