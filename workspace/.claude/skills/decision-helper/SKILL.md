# Decision Helper

دو حالت دارد؛ مناسب را انتخاب کن:
- **A. سنجیدن ایده** (پروژه جانبی، استارتاپ، محصول، سرمایه‌گذاری): پنل ۵ نفره → حکم.
- **B. تصمیم سخت** (کار، مهاجرت، رابطه، خرید بزرگ — وقتی همه گزینه‌ها هزینه دارند): چارچوب ۱۰/۱۰/۱۰.

پیش‌فرض Claude موافقت است؛ این skill عمداً برعکس است. صادق و مستقیم باش.

---

## A. پنل ۵ زاویه‌ای (Roast)

### ۱. خلاصه ایده
فقط چیزهایی که هنوز نمی‌دانی را در یک پیام بپرس (حداکثر ۴): ایده در ۱-۲ جمله · برای چه کسی و مدل درآمد · مزیت کاربر (مهارت، مخاطب، دارایی) · محدودیت‌ها (بودجه، زمان، چقدر زود درآمد لازم است). اطلاعات `memory/profile.md` را هم در نظر بگیر. یک خلاصه یک‌پاراگرافی بساز.

### ۲. پنل — ۵ subagent **موازی** (`general-purpose`)، همه با همان خلاصه
هر کدام برگرداند: موضع یک‌خطی، ۳-۵ نکته تیز، مهم‌ترین چیزی که کاربر باید بشنود، امتیاز ۱-۱۰.
1. **منتقد** — «چه چیزی این را می‌کشد؟» فرض کن شکست می‌خورد؛ نقص‌های مرگبار و فرض‌های اشتباه.
2. **حامی** — «نسخه ۱۰ برابری چیست؟» قوی‌ترین دفاع و فرصت‌های پنهان.
3. **تحلیلگر** — بدون وب، از اصول اولیه: منطق، انگیزه‌ها، ریاضیات.
4. **محقق** — با WebSearch: رقبا، قیمت‌ها، نشانه‌های تقاضا؛ با منبع. (برای بازار ایران، شرایط محلی را هم بسنج.)
5. **مشتری** — در نقش مشتری هدف، اول‌شخص: واقعاً پول می‌دهم؟ اعتراض واقعی‌ام چیست؟

### ۳. حکم (تو قاضی هستی — میانگین ساده نگیر)
- امتیاز ترکیبی = مشتری×۰٫۳۰ + منتقد×۰٫۲۵ + محقق×۰٫۲۰ + تحلیلگر×۰٫۱۵ + حامی×۰٫۱۰
- ≥۷ → GO، ۴٫۵ تا ۷ → RESHAPE، کمتر → KILL
- **وتوها** (فقط پایین می‌آورند): مشتری ≤۳ (خریداری نیست)، منتقد ≤۲ (نقص مرگبار)، تحلیلگر ≤۲ (منطق نمی‌خواند) → GO نمی‌تواند باشد. مشتری ≤۲ و ترکیبی <۴٫۵ → KILL.
- اطمینان از میزان توافق: اختلاف بیشینه و کمینه ≤۲ زیاد، ≤۵ متوسط، بیشتر کم. GOِ وتوشده هرگز اطمینان زیاد ندارد. بیشترین اختلاف را «تنش اصلی» بنام و حلش کن.
- روش‌ها: `references/verdict_synthesis_method.md`، `references/adversarial_panel_canon.md`، `references/cheapest_test_canon.md`

```
## حکم: GO / RESHAPE / KILL — اطمینان: کم/متوسط/زیاد
**در یک خط:** ...
**چرا:** (۲-۳ جمله، حل تنش پنل)
**بزرگ‌ترین ریسک:** ...   **بزرگ‌ترین فرصت:** ...
**حساب پول:** قیمت تقریبی، زمان تا اولین درآمد، آیا کاربر سریع می‌تواند بسازد
**ارزان‌ترین آزمون ۴۸ ساعته:** کوچک‌ترین کار برای سنجیدن پرریسک‌ترین فرض، با معیار قبول/رد
**اگر RESHAPE:** تغییر مشخصی که نقص را رفع می‌کند
منتقد X · حامی X · تحلیلگر X · محقق X · مشتری X
```

## B. تصمیم سخت

1. **برگشت‌پذیری:** برگشت‌پذیر (امتحان کن و یاد بگیر) / نیمه‌برگشت‌پذیر / برگشت‌ناپذیر (دقت بیشتر قبل از اقدام). «اگر تصمیم برگشت‌پذیر را مثل برگشت‌ناپذیر می‌بینی، داری از آن فرار می‌کنی.»
2. **۱۰/۱۰/۱۰:** برای هر گزینه: ۱۰ دقیقه بعد چه حسی داری؟ ۱۰ ماه بعد چه اثری؟ ۱۰ سال بعد درست بوده؟ (حس ۱۰ دقیقه‌ای کم‌اعتمادترین است.)
3. **آزمون آدم تازه‌وارد:** کسی بدون وابستگی عاطفی و هزینه ازدست‌رفته، چه می‌کرد؟ اگر واضح است، چرا هنوز نکرده‌ای؟
4. **نقشه اثر بر افراد:** برای هر گزینه، اثر بر خودت، خانواده، همکاران و … (فهرست، نه جدول).
5. **کمینه‌کردن پشیمانی:** در ۸۰ سالگی از کدام انتخاب کمتر پشیمانی؟
6. **آزمون پیام اعلام:** پیامی که تصمیم را به آدم‌های درگیر اعلام می‌کند را بنویس. اگر نمی‌توانی بنویسی، آماده تصمیم نیستی.
7. **برنامه ارتباط و قدم بعدی:** اول به چه کسی، چطور، چه می‌گویی، و قدم بعدی دقیق.

نشانه‌های فرار از تصمیم: بیش از یک ماه هر هفته به آن فکر کردن، منتظر «داده بیشتر» ماندن که هیچ‌وقت کافی نیست، امید به حل خودبه‌خود. **هزینه تأخیر تقریباً همیشه از هزینه تصمیم بیشتر است.**

برای تصمیم‌های مالی/حقوقی/پزشکی پرریسک، داده‌ها را با WebSearch یا skill `deep-research` محکم کن و مشورت متخصص را پیشنهاد بده.

## ثبت
تصمیم نهایی، دلایل و فرض‌ها را در `notes/decisions/YYYY-MM-DD-<slug>.md` ذخیره کن و یک یادآور ۳ ماه بعد برای بازبینی تصمیم بگذار (آیا فرض‌ها درست درآمدند؟).
